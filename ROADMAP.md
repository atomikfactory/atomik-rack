# Roadmap

This is a list of intentions, not promises. There are no dates. The phases are in rough priority order, but items inside a phase are not ordered. Ideas and help are welcome: open a discussion or an issue before starting something big.

Design questions that shape several items (plugin batching, ASIO licensing, delay compensation, the patch format, modulation, note naming, format cadence and more) are recorded with their options and status in the [decision log](docs/DECISIONS.md).

## Phase 1: Stability and platforms

- **Sync follow-ups.** Tracking the phase of an incoming MIDI clock (a sender whose tempo wanders can drift from the song), and audio clips that play while following an external clock (they are silent today).
- **Plugin sandbox follow-ups.** Run the sandbox on Linux and macOS for real (the wake-up and stdout redirection are compile-checked only), optional grouping of several instances in one process, and embedding sandboxed editors where the platform allows it.
- **macOS and Linux verification.** Linux has been tried on Ubuntu 26.04 only; other distributions, audio setups and real plugins still need checking. macOS compiles and is linted but has not been run on a Mac. Verifying and fixing both is a priority.
- **VST3 on Wayland.** Plugin editor embedding on native Wayland (sandboxed editors already run through XWayland; in-process editors and sessions without `DISPLAY` fall back to the parameter pane). Editors that need file-descriptor handlers now run on Linux; they still need checking with more real plugins.
- **Recovery and fault follow-ups.** A recovered snapshot that opens with its bundle's audio (today its audio clips show as missing), a recovered recording as one undo step (today two), a scratch folder preference, going back to a chosen audio device by itself when it returns (today the settings keep it and a restart picks it up), and per-device containment of a panic outside `process` (today the stream-level guard silences everything).
- **Signed builds.** The pipeline is wired (Authenticode or Azure Trusted Signing, Developer ID signing with notarisation, a GPG signature of the checksums) and skips each step until its secrets exist; what is left is to obtain the certificates (a Windows code-signing certificate or an Azure signing account, an Apple Developer ID account, a GPG key), add them to the `release-signing` environment and confirm the first signed release on real machines. Until then the builds are unsigned.

## Phase 2: The sequencer

- **Automation recording follow-ups.** A preference for the thinning amount, and a touch that starts at the press instead of the first move (needs a press and release signal from every control, plugin windows included).
- **MIDI controller data follow-ups.** Controller lanes without a note clip, selecting several points with copy, paste and thinning, the mod wheel in the sampler, a destination for channel and poly pressure (the instruments track it but nothing reads it yet), a command and key for the controller area, and MPE (per-note expression) lanes.
- **Loop recording and takes follow-ups.** An overlapped constant-power crossfade at audio comp splices (it needs the engine to mix two regions; today a splice is a 5 ms fade out and in), adding a later recording pass to an existing group, opening a take in the piano roll or the sample editor, a waveform in the audio take rows, a command and key for the take rows, comping several tracks at once, and takes for automation passes (a loop recording of automation still lays layered clips).
- **Quantize and groove follow-ups.** A live, non-destructive groove per track or clip (a groove name saved on the track and applied when the song is flattened, so changing a template re-times every track that uses it without touching the notes; today a clip's step-grid swing is the only live swing and a groove is baked in), controller lane points that move with their notes, a text field to name and rename a groove, a groove from a MIDI file or an audio loop, per-note-length and legato options, humanize of lengths, a quantize button in the arrangement's toolbar (the piano roll has one), tooltips on the roll's toolbar buttons, and bar lines that follow meter changes for the swing parity (it counts steps from the start of the song).
- **MIDI file follow-ups.** A choice of export resolution (960 or 480 ticks per quarter note, for hardware that dislikes 15 360), the file browser listing `.mid` files for dragging from the panel, a drop onto a lane that imports into that track at the drop position, range markers exported, program changes and bank selects, per-note expression (MPE) and SysEx kept, and a groove taken from a MIDI file (see Quantize and groove follow-ups).
- **Arrangement restructuring follow-ups.** A percent dialog and edge-drag scaling for Scale Tempo, a Workflow preference for the reverse mode, joining audio clips and draggable crossfade zones.
- **Rack editing follow-ups.** The "+" handles between devices, a Create submenu, unfolding after hovering a cable drag, and replacing a device from the track header or from a library item.
- **Looped clip follow-ups.** Looping an audio take, and converting an audio loop into one clip.
- **Track organisation follow-ups.** Dragging folders with the mouse (tracks drag by their headers; a folder moves with Move Track Up and Down), a folder that mutes and solos its tracks by itself (today the buttons set the flags on every track), an automatic colour for new tracks, stacked bars for clips in tracks under 32 px, routing the tracks of a folder to an output bus and a folder-level fader (see Phase 4), a folder colour that the tracks without their own colour inherit, a comment of several lines, a rubber band over headers to select tracks, a colour picker with any colour (the palette has six), and folding the controller lanes in the piano roll the way automation lanes fold in the arrangement.
- **Recording and editing follow-ups.** Masked notes dimmed and note tails drawn in the piano roll, Piano Keys as a floating window with its octave, velocity and visibility remembered, a Save / Don't Save / Cancel box with those words on every platform (Windows shows Yes / No / Cancel), the inspector's fades with a ms/ticks switch, and a smaller edit than the whole note list per inspector step on very large clips.
- **Automation lane and gesture follow-ups.** A draggable handle for a lane's static value, range select on a lane and Extend to Next/Previous Clip, a plain drag on an empty lane that starts a rubber band, an option to turn note audition off in the piano roll, trimming the start of several audio clips at once, snap settings remembered between sessions, and the mute, magnify and hand tools.
- **Note lane follow-ups.** Reordering and duplicating lanes, a solo per lane, a lane of its own colour, and recording to several lanes at once (today a take goes to the one selected lane).

## Phase 3: Audio

- **Time-stretch follow-ups.** Warp markers are edited by hand in the audio clip editor's Slice mode; still to come are the Vocal and Comp modes of the editor, a warp toggle and tempo field in the clip inspector, the tempo of AIFF files on import, warping a reversed clip (today reverse and warp exclude each other); a real-time stretch for the moment before a buffer is rendered (today the clip plays unwarped until the worker is done); formant-preserving pitch shift; swing and groove (not only the grid and strength) in Quantize Audio; stereo-linked phase locking in the Tonal mode; and warping streamed assets without holding the rendered clip in memory (the cache holds 512 MiB).
- **Audio editing follow-ups.** A crossfade length handle on the clip (today the overlap sets it); a separate curve for the fade in and the fade out; envelope points that snap to the grid and select several at once; a streaming strip silence detector (today it reads the clip's span into memory); a normalise target setting (0 dBFS today) and RMS or loudness normalise; and a crossfade at comp splices (see Loop recording and takes follow-ups).
- **Freeze and bounce follow-ups.** Bounce in place of a time range (today whole clips), freezing a container instrument or a container effect in the chain, a freeze that keeps the sends or the whole channel strip as an option, a render that follows tempo changes (today the tempo is locked while a track is frozen), freezing with in-process plugins (today the sandbox is needed), a freeze that does not stop playback when the engine restarts, re-rendering a frozen track in place, and a latency-compensated mix (a frozen track is aligned to the others but the mix is that much earlier).
- **Stem and selection export.** Export every track, bus or a selected range as separate files, in WAV, FLAC and MP3, with dither and loudness reporting.
- **Audio to notes follow-ups.** Polyphonic extraction (chords and several voices), the pitch bend of a note kept as a bend lane (today the pitch is rounded to a semitone), a re-attack of one pitch with a shorter dip in level than 20 ms, a snare struck with a hat (a hit is one drum, except a kick with a hat), drum kit mapping options (other key maps than General MIDI, toms and cymbals, a drum machine track with the pads filled from the audio), notes from several selected clips at once, a progress readout and cancel for a long clip, and analysis of the whole of a clip longer than ten minutes.
- **Spectrum and metering follow-ups.** The same meters as console panels (a spectrum and a phase meter on a channel or a bus without an insert; today they are devices in a chain, and the console keeps its peak and RMS meters), a spectrogram (a scrolling time-frequency view), a reference curve to compare the spectrum against (a stored curve or a second device), a loudness history graph with the range (LRA) and a target line, meters for plugin devices (they have no scope tap), a larger FFT (16384 and up) and a smoothing across bins for the fine trace, the K-weighting as an option on the spectrum, and the display settings as user-saved presets.

## Phase 4: Mixing and control

- **Mixer groups follow-ups.** Automation of the group fader (a group is not a device today, so its level is not a lane target; it needs a device or a new lane target kind), a link-faders mode that stays on (selected strips already move together by the same dB, but only while they are selected), groups of groups, a group that follows a track folder, a VCA that routes its members to a bus (a group bus), a group chip on the device headers of the rack, Create VCA in the track header and folder context menus, assigning by dragging a track header, and menu items that name the group (today Add to VCA and Delete VCA take the id as an argument, or act on the last group and the selection's groups).
- **Console editing follow-ups.** Cut, copy, paste and duplicate of strips from the console (Delete is there; the rest wait), Ctrl-drag of a strip to copy it, a RACK and SEQ jump button and a colour plate on each strip header, bus colours in the output selector, a remote-control base for the strip surface, more than four inserts per strip with a scrolling INSERTS section (a chain read back from cables can hold 16, but an edit stops at four and the console draws four rows), auto make-up and an E band mode on the strip, key-input auto-on for channels and buses, VU and PPM ballistics, a peak reset and a release Auto on the master, a level CV on the master, a total delay compensation readout, and sorting the selected device groups.
- **Channel strip upgrades follow-ups.** A delay-compensated `insert.bypass` on the strip itself (the console now bypasses the effects instead; the strip would need to be told the latency of its insert return), bypass and a B for container effects (a container has no bypass), a parallel compressor with a key input, lookahead (with its latency matched), a peak detector choice and a gain-reduction meter in the console, a pre-insert tap and a choice of tap, an EQ or saturation on the parallel path, a per-side polarity for a stereo strip, a value readout on the console's trim knob at rest (it shows while dragging and in the rack), and bypass-all that also covers the dynamics and EQ sections.
- **Snapshots follow-ups.** The parameters of the effect devices in the snapshot (an option to include them; today only their bypass), snapshots that capture the output routing and the insert chains' members, a morph between two snapshots over a time, snapshot recall as an automation lane or a marker action, a per-snapshot note and colour, more than 16 and a scrolling chip bar (chips that do not fit the bar are left out; the menu commands reach all of them), default keys for Recall Next and Previous and Compare A/B, and A/B comparison of a single strip.
- **MIDI learn and control surface follow-ups.** The older hardware-user-interface protocol (HUI) and other surface protocols, OSC as a transport for surfaces and tablets, level meters, flip and the function keys on the eight-fader driver, a second unit (an extender) and a choice of what the V-pots drive (sends, plugin parameters), NRPN and RPN sources, mapping the parameters of a plugin whose editor window is open (today the parameter pane, the console and the rack are learnable), per-plugin mapping presets that follow the plugin rather than the rack position, a merge group for the tempo and for several controls moved at once, MMC (machine control) input as a transport, and the mapping panel's port and channel fields.
- **Macro and parameter workflow follow-ups.** Per-track macro banks made for you (today a bank is a rack device, and the right-click menu uses the current bank), macros that drive the params of a container's inside or another bank's macro (the container keeps its own macros), a curve other than linear in the plain value (the cutoff moves linearly in Hz), a smoothing time per assignment, a direct edit of a driven param that moves its range instead of being refused, an automation lane on a driven param that the macro scales, a macro that morphs between two values of several params (a snapshot of a chain), assigning by dragging a knob onto a macro, a range edit by dragging in the panel and a numeric entry, macros and assignments in device presets, following the selection from the piano roll and the sample editor, lanes for effects and channel strips without a macro (a track needs a notes input today), saved and recent searches, search by value or by what has automation, a search that also lists clips, markers and tempo, and the search of a parameter pane reaching a plugin's params that the project has not saved a layout row for.
- **Feedback routing.** A supported way to route audio back on itself (with a mandatory delay stage) instead of the current rejection of loops.

## Phase 5: Devices

New original devices built from the existing DSP blocks, grouped by the gap they fill.

- **Utility and CV.** An LFO is done; still missing are a CV mixer and merger, a splitter, an attenuator and inverter, a CV math device, a quantizer with scales, a sample-and-hold, a slew limiter, a gate and trigger processor, and an audio-rate envelope follower.
- **Pattern and note tools.** Done: a note filter (transpose and key and velocity filters), a key and chord device, a note repeater and a note delay, a CV sequencer with two curve rows and chained patterns, a drum generator, a bypass on every player, and players that stack on an instrument. Still to come: recording a player's output into a clip (send to track), copy and paste of CV curves with their pattern, and controls for a drum pattern's resolution and swing.
- **Instruments.** Done: a wavetable synth, an FM synth and a granular sampler. Still to do: a physical-modelling instrument, an organ, a monosynth with a mod matrix, and a semi-modular synth built from the CV devices.
- **Grain sampler follow-ups.** Click and drag on the waveform to set the position, a mono/legato mode with glide, a per-voice LFO, several samples chosen by key or velocity range (today the first matching zone plays), spectral or pitch-synchronous grains, a longer grain trail on the panel than 13, a freeze that holds the last grains of a live input, and more factory sounds.
- **FM synth follow-ups.** Six operators, waveforms beyond the sine, an envelope with more than four stages, a unison and chorus stage, a mod matrix beyond the fixed targets, more factory sounds, a pick list for the sound and the algorithm (today a click cycles), a display that shows the modulated indices of a sounding voice, polyphonic glide, and 2x oversampling for the brightest patches instead of the index limiter.
- **Wavetable synth follow-ups.** Import a WAV as a table (frames of 2048 samples) and a table editor, per-oscillator unison settings, a position display that shows the modulated frame of a sounding voice, a pick list for the table choice (today a click cycles), a mod matrix beyond the fixed targets, wavetable morphing between two tables, and a table change that crossfades instead of clicking.
- **Effects.** Pitch shifter, vocoder, tape and saturation, rotary speaker, auto-filter and envelope filter, gate and expander, transient shaper, de-esser, a standalone limiter, a multiband dynamics device, a convolution reverb with an impulse browser, a tuner, and a stereo imager.
- **Instrument patches.** Done: a single-device patch applied in place, saved, stepped and browsed with audition from a patch strip on every device. Still to come: tags and search over patches, factory banks that ship with the application, and resetting a plugin's live instance with Reset Device.

## Phase 6: Library and projects

- **Library of devices, patches and projects.** Done: the browser lists the built-in devices and the patches, containers, clips and projects of a library folder; Save to Library writes the selected devices, a container or a note clip with their samples; items load by double click or drag as one undo step, and projects open after the unsaved-changes question. Still to come: factory content, previews of clips and patches, and deleting items from the browser.
- **Project templates and a start screen.** Templates for common set-ups and a start screen (the recent-projects list is done: File > Open Recent, and an option to reopen the last project at start-up).
- **Collect and relocate.** Copy every file a project uses into its bundle, and relocate a project without breaking its links.
- **Song information.** Notes, credits and a version history inside the project.

## Phase 7: Ecosystem and device parity (last)

This phase comes last on purpose: it builds on everything above and on a stable public API.

- **A stable device SDK.** A versioned, documented interface and a package format so that third parties can write and distribute devices that run natively in the rack, with their own front and back panel, parameters, CV and note sockets, and presets. This extends [docs/EXTENDING.md](docs/EXTENDING.md).
- **Device packages and a store-less installer.** Install, update and remove device packages from a folder or an archive, with signature and version checks.
- **Factory device parity.** Fill the remaining gaps in the factory set so that each usual category of device (instruments, effects, players, utilities) has at least one original design, and add the deeper variants that earlier phases only started.
- **Matching other devices.** Equivalents of well-known devices and device formats from other platforms, written as original work: a parameter-compatible mode where it helps users move their patches, and importers for patch files that are openly documented. Anything that needs proprietary data stays out (see HI-4 in the README).

## Quality

- Keep the hard invariants (real-time safety, determinism, graph validity, originality) enforced by tests as the feature set grows.
- Grow the automated checks that run on macOS and Linux.
