# Roadmap

This is a list of intentions, not promises. There are no dates. The phases are in rough priority order, but items inside a phase are not ordered. Ideas and help are welcome: open a discussion or an issue before starting something big.

Design questions that shape several items (plugin batching, ASIO licensing, delay compensation, the patch format, modulation, note naming, format cadence and more) are recorded with their options and status in the [decision log](docs/DECISIONS.md).

## Phase 1: Stability and platforms

- **Sync follow-ups.** Audio clips stretched to the followed tempo (they play at their own rate and are re-synchronised at each clip start, locate and loop wrap, so a clip of many bars drifts when the two tempos differ), streamed audio while following (silent today), a lock for a sender that sends no Start or Song Position Pointer (the song runs on the measured tempo alone), and a setting for how tightly the song is held to the clock.
- **Plugin sandbox follow-ups.** Run the sandbox on Linux and macOS for real (the wake-up and stdout redirection are compile-checked only), optional grouping of several instances in one process, and embedding sandboxed editors where the platform allows it.
- **macOS and wider Linux verification.** Ubuntu 26.04 is a main platform beside Windows; other distributions and audio setups still need checking. macOS is built, linted and tested only on GitHub Actions and has not been run on a Mac by hand. Verifying and fixing both is a priority.
- **VST3 on Wayland.** Plugin editor embedding on native Wayland (sandboxed editors already run through XWayland; in-process editors and sessions without `DISPLAY` fall back to the parameter pane). Editors that need file-descriptor handlers now run on Linux; they still need checking with more real plugins.
- **Signed builds.** The pipeline is wired (Authenticode or Azure Trusted Signing, Developer ID signing with notarisation, a GPG signature of the checksums) and skips each step until its secrets exist; what is left is to obtain the certificates (a Windows code-signing certificate or an Azure signing account, an Apple Developer ID account, a GPG key), add them to the `release-signing` environment and confirm the first signed release on real machines. Until then the builds are unsigned.

## Phase 2: The sequencer

- **Automation recording follow-ups.** A touch that starts at the press instead of the first move (needs a press and release signal from every control, plugin windows included).
- **MIDI controller data follow-ups.** MPE (per-note expression) lanes, the CC badge on a compact track row (the badge needs a row of 52 px or more), and snapping of the points of the track lanes to the bar lines of a changing meter (the Bar and Beat snap counts from the first meter).
- **Quantize and groove follow-ups.** A groove from an audio loop, device-parameter lanes and a track's own controller lanes that move with the notes of a quantize (only the lanes of a note clip do today), and a quantize of the note lengths to a length grid (the grid per note picks the start grid from each note's length).
- **MIDI file follow-ups.** Per-note expression (MPE) kept, and typing the bytes of a SysEx message (the piano roll adds General MIDI System On, moves, deletes and clears messages).
- **Note lane follow-ups.** An S button on the chip of lane 0 (the chip shares the header's second line with the track's own buttons and has no room for a third control: use the Solo Lane menu item), a click on the record dot of a lane header to arm it (the dot shows the armed state; the Record to Lane menu item arms it today), and splitting the incoming notes between armed lanes by a rule (every armed lane gets the whole take today).

## Phase 3: Audio

- **Time-stretch follow-ups.** Warp markers are edited by hand in the audio clip editor's Slice mode; still to come are the Vocal and Comp modes of the editor and slicing for a reversed clip (a reversed clip can be warped, transposed and quantized, but the slice editor and Clip to Loop Slicer still refuse it); a real-time stretcher that keeps the pitch (WSOLA: the preview that plays before a clip's buffer is rendered resamples through the warp markers, so a transposed clip is at the wrong pitch until the buffer is ready); formant-preserving pitch shift; stereo-linked phase locking in the Tonal mode; and warping streamed assets without holding the rendered clip in memory (the cache holds 512 MiB).
- **Freeze and bounce follow-ups.** A freeze that also bakes the sends into the render (a strip with a send on into a return, or a parallel channel, is refused when the strip is baked in, since their signal would go silent), a render that follows tempo changes (today the tempo is locked while a track is frozen), freezing with in-process plugins (today the sandbox is needed), and a latency-compensated mix (a frozen track is aligned to the others but the mix is that much earlier).
- **Stem and selection export follow-ups.** Per-strip stems in WAV, AIFF and FLAC with dither, stems between the locators or over the selected time range, the selection as one file and a loudness report are done. Still to come: MP3 (held back until its licence is settled), and the selection in the MCP export tool (it takes the song or the locators).
- **Audio to notes follow-ups.** Polyphonic extraction (chords and several voices), a re-attack of one pitch with a shorter dip in level than 20 ms, a snare struck with a hat (a hit is one drum, except a kick with a hat), and a drum machine track with the pads filled from the audio.
- **Spectrum and metering follow-ups.** A spectrogram, a stored reference curve, a loudness history graph with the range and a target line, the K-weighting, a 16384-point FFT with smoothing across bins and the display settings as user presets are done. Still to come: the same meters as console panels (a spectrum and a phase meter on a channel or a bus without an insert; today they are devices in a chain, and the console keeps its peak and RMS meters), a second device as the reference curve, meters for plugin devices (they have no scope tap), and FFT sizes above 16384.

## Phase 4: Mixing and control

- **Mixer groups follow-ups.** Groups of groups (a group is a flat list of strips, so a group cannot hold another one yet), and a group solo lane that silences the other strips: the lane switches the solo of the group's own members, while the strips outside the group are silenced from the stored solo state only, as for a strip's own solo lane.
- **Console editing follow-ups.** A remote-control base for the strip surface, and sorting the selected device groups.
- **Channel strip upgrades follow-ups.** A delay-compensated `insert.bypass` on the strip itself (the console now bypasses the effects instead; the strip would need to be told the latency of its insert return), a pre-insert tap that stays aligned when the inserts add latency (today it is aligned only without insert latency), a bypassed container that keeps the latency of its inside, and an EQ or saturation on the parallel path.
- **Snapshots follow-ups.** Still to come: a bounce that recalls at markers and lane points, snapshots that add or remove the effects of a chain (today a recall moves cables between the devices the rack has), a snapshot lane for ids past 64, and a lane value that shows the snapshot's colour.
- **MIDI learn and control surface follow-ups.** Several surfaces at once, a generic driver, command mappings, NRPN and RPN sources, MMC input as a transport, the mapping panel's port and channel fields and the preset of one device are done. Still to come: the older hardware-user-interface protocol (HUI) and other surface protocols, OSC as a transport for surfaces and tablets, level meters, flip and the function keys on the eight-fader driver, a second unit (an extender) and a choice of what the V-pots drive (sends, plugin parameters), mapping the parameters of a plugin whose editor window is open (today the parameter pane, the console and the rack are learnable), a merge group for the tempo and for several controls moved at once, an MMC device number and a switch to turn MMC off per port, and NRPN and RPN sources on a control surface's own driver (the generic driver feeds them like a port).
- **Macro and parameter workflow follow-ups.** Per-track macro banks made for you (today a bank is a rack device, and the right-click menu uses the current bank), macros that drive another bank's macro (the container keeps its own macros, and a bank can now drive the params inside a container), the knob of a driven param showing the sum of its lane and the macro while the song plays, a macro that morphs between two values of several params (a snapshot of a chain), a direct edit of a driven control in the mixer and the plugin parameter pane (the rack does it now), a curve and a smoothing time for a container's macros, macros and assignments in device presets, following the selection from the piano roll and the sample editor, lanes for effects and channel strips without a macro (a track needs a notes input today), saved and recent searches, search by value or by what has automation, a search that also lists clips, markers and tempo, and the search of a parameter pane reaching a plugin's params that the project has not saved a layout row for.
- **Feedback routing follow-ups.** A feedback delay shorter than one engine batch (the stage order needs a batch of room), delay compensation that aligns a loop with the paths around it (a loop is not compensated today), a feedback send and return pair for two far apart places of a rack (a cable joins them today), a distinct look for the cable that closes a loop, and a damping filter and a ducking option in the loop.

## Phase 5: Devices

New original devices built from the existing DSP blocks, grouped by the gap they fill.

- **Utility and CV.** Done: an LFO, a CV mixer and merger, a splitter and an attenuator and inverter (the CV Split/Merge device), CV math (add, subtract, multiply, minimum, maximum, absolute, scale and offset), a quantizer that uses the piano roll's scales or a custom scale of its own, with a hysteresis, a sample-and-hold (or track-and-hold) with a trigger, free or tempo clock, a slew limiter with separate rise and fall, a gate and trigger processor (logic, divide, delay, length, trigger out) and an audio-rate envelope follower (peak or RMS, attack and release, CV and gate). Still to come: a delay and length in note values on the gate processor, scales saved in the song to share between quantizers, and a hold that tracks for a set length instead of half a cycle.
- **Pattern and note tools.** Done: a note filter (transpose and key and velocity filters), a key and chord device, a note repeater and a note delay, a CV sequencer with two curve rows and chained patterns, a drum generator, a bypass on every player, and players that stack on an instrument. A play button on every player runs it, and the players after it in the stack, on a clock of their own while the song is stopped, so a player can be heard through its track's instrument without playing the song. Send Players to Track and controls for a drum generator's resolution and shuffle are done too, and so is copy and paste of a CV sequencer pattern with its curves (on the panel and in the grid editor, one undo step). Not done: copying one curve row alone, and a CLEAR that also clears the curves.
- **Instruments.** Done: a wavetable synth, an FM synth, a granular sampler, a monosynth with a modulation matrix (Mono Bass), a semi-modular synth built from the CV devices and a drawbar organ (nine drawbars in equal temperament, percussion on the second or third harmonic, key click, a vibrato and chorus scanner, overdrive, sustain, volume and expression, and six factory sounds), which plays straight into the rotary speaker. Still to do: a physical-modelling instrument. Not done in the organ: a panel with real drawbar sliders (today the drawbars are stepped knobs), tonewheel leakage and foldback, a second manual and a pedal bass, and a mod wheel that sets the scanner depth or the rotary speed.
- **Grain sampler follow-ups.** Done: a click or a drag on the waveform sets the position, mono and legato play, a layered zone mode, several zones built on the panel (a drop with the copy modifier held adds a zone; the sample editor sets their key and velocity ranges), a spray band dragged by its edges on the waveform, and pick lists for the play mode and the zone mode. Still to do: spectral or pitch-synchronous grains, a freeze that holds the last grains of a live input, a legato note that crosses to another sample without a restart, more factory sounds, and the copy modifier during a file drag on systems that do not report modifiers then (the drop replaces there).
- **FM synth follow-ups.** Done: six waveforms per operator (sine, half, rectified, squeezed sine, triangle, soft square), polyphonic glide, a stereo chorus, 2x and 4x oversampling (2x widens the index limiter; both report their latency), four more factory sounds, pick lists for the sound and the algorithm (also used by the organ and grain sampler sounds), a unison stage (up to seven detuned, panned copies of every voice) and a slope after each operator's decay, a fifth envelope stage. Still to do: six operators, a full multi-stage envelope with several breakpoints, a mod matrix beyond the fixed targets, and a display that shows the modulated indices of a sounding voice.
- **Wavetable synth follow-ups.** Done: a sample dropped on the device is a table (cut into frames of 2048 samples, 16 frames used, saved with the project's audio), a pick list for the table choice, separate unison settings for oscillator 2, a table change that crossfades over 12 ms instead of clicking, and a display that shows the modulated frame of the newest sounding voice. Still to do: a table editor, a mod matrix beyond the fixed targets, wavetable morphing between two tables, more than 16 frames per imported table, a curve for the imported table on the panel, and a fade when the imported sample itself is replaced.
- **Effects.** Done: a space reverb, a convolution reverb, a vocoder, a gate and expander, an envelope filter, a limiter and multiband dynamics inside Mastering, a stereo imager (Stereo Tool), tape saturation through the distortion curves and Character, a transient shaper, a de-esser, an auto-filter, a tuner device, a real-time pitch shifter with a reported latency, a rotary speaker (horn and drum rotors with slow, fast and run-up, Doppler and level movement, crossover, drive, microphone spread and a speed CV input) and a dynamic EQ (five bands, a low shelf, three bells and a high shelf, each cutting or lifting with the level of its own band or of a key input, in stereo, mid or side, with a panel of static and live curves over the input and key spectra). Not done in the rotary speaker: a cabinet resonance model, a microphone distance control and a dry path aligned to the wet one. Not done in the dynamic EQ: low and high cuts, a hold time and a look-ahead.
- **Instrument patches.** Done: a single-device patch applied in place, saved, stepped and browsed with audition from a patch strip on every device. Reset Device works on built-in devices, and the browser filters by tag, category and kind. A factory bank of 27 original patches for the poly synth, mono bass, dual layer, FM synth, grain sampler, wavetable synth, organ and semi-modular synth, four drum kits for the drum machine and ten effect chains as containers ships with the application (see the library below). Still to come: a fuller search over patches, a factory bank for the sampler with its own recorded samples, and resetting a plugin's live instance.

## Phase 7: Ecosystem and device parity (last)

This phase comes last on purpose: it builds on everything above and on a stable public API.

- **A stable device SDK.** A versioned, documented interface and a package format so that third parties can write and distribute devices that run natively in the rack, with their own front and back panel, parameters, CV and note sockets, and presets. This extends [docs/EXTENDING.md](docs/EXTENDING.md).
- **Device packages and a store-less installer.** Install, update and remove device packages from a folder or an archive, with signature and version checks.
- **Factory device parity.** Fill the remaining gaps in the factory set so that each usual category of device (instruments, effects, players, utilities) has at least one original design, and add the deeper variants that earlier phases only started.
- **Matching other devices.** Equivalents of well-known devices and device formats from other platforms, written as original work: a parameter-compatible mode where it helps users move their patches, and importers for patch files that are openly documented. Anything that needs proprietary data stays out (see HI-4 in the README).

## Quality

- Keep the hard invariants (real-time safety, determinism, graph validity, originality) enforced by tests as the feature set grows.
- Grow the automated checks that run on macOS and Linux.
- **Release testing.** The manual test protocol in [docs/RELEASE-TESTING.md](docs/RELEASE-TESTING.md) covers what needs a device, a real plugin, a display or an installer; the release workflow does not require a filled report yet.
- **Interface follow-ups.** The menus and label fits that still estimate their width, a split of the large view files, a view table indexed by pane, screen-reader support, and removing the dependency of the UI crate on the DSP crate (the tuner, FM, strip EQ, shaper, grain and wavetable displays still read it).
