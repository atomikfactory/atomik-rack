# Examples

Example projects and patches for Atomik Rack. Run commands are repo-relative; run them from the repository root.

## Audio fixtures are generated

None of the audio in this directory comes from a third party. Every `.wav` file under `examples/projects/*/Audio/` is **procedurally generated** by the project's own code (synthesised from oscillators, noise and envelopes by a function in the test named below) and is released under CC0 together with the rest of the example data. The files are named by the SHA-256 of their decoded content, so a regenerated file has the same name. The projects without an `Audio/` folder contain no audio at all.

To regenerate a project and its audio after an intentional change, run its test with `ATOMIK_UPDATE_GOLDEN=1`, for example:

```sh
ATOMIK_UPDATE_GOLDEN=1 cargo test -p atomik-render --test drum_demo regenerate
```

Without that variable the same tests check that the committed files are exactly what the generator produces.

## Projects

Open a project with `cargo run --release -p atomik-app -- <file>`, or render it with `cargo run --release -p atomik-render -- <file> -o out.wav`.

| Project | What it shows | Audio | Generated by |
|---|---|---|---|
| `projects/demo.atomik` | A small song with notes and a console: synth tracks through channel strips into the master. | none | a project file saved by the application |
| `projects/audio-demo.atomik` + `projects/audio-demo/` | The demo song plus an audio track with a one-bar drum and bass loop (a bundle folder). | one generated mono loop | `crates/render/tests/audio_demo.rs` (`regenerate`) |
| `projects/sampler-demo/sampler-demo.atomik` | Two samplers with generated samples: plucks auto-mapped by note name, layers, a loop. | five generated samples | `crates/render/tests/sampler_demo.rs` (`regenerate`) |
| `projects/drum-demo/drum-demo.atomik` | A drum machine with a swung two-bar pattern, a hat choke group and the snare on its own console channel. | five generated drum sounds | `crates/render/tests/drum_demo.rs` (`regenerate`) |
| `projects/slicer-demo/slicer-demo.atomik` | A generated two-bar drum loop cut at its transients and played at another tempo, with a reversed slice. | one generated drum loop | `crates/render/tests/slicer_demo.rs` (`regenerate`) |
| `projects/fx-demo/fx-demo.atomik` | An eight-bar song using the reverb, compressor with a kick sidechain, EQ, distortion, modulation and the mastering suite. | four generated drum sounds | `crates/render/tests/fx_demo.rs` (`regenerate`) |
| `projects/player-demo/player-demo.atomik` | The step sequencer and arpeggiator driving synths. | none | `crates/render/tests/player_demo.rs` (`regenerate`) |
| `projects/container-demo/container-demo.atomik` | The container device: an inner rack, macros and note splits. | none | `crates/render/tests/container_demo.rs` (`regenerate`) |
| `projects/character-demo/character-demo.atomik` | The Character effect automated through a container, patched with a note CV, and in the long latency class. See its README. | none | `crates/render/tests/character_demo.rs` (`regenerate`) |
| `projects/master-demo/master-demo.atomik` | The starter project: a visible Master section, instruments made by the creation chain, a reverb on send and return 1. See its README. | none | `crates/render/tests/master_demo.rs` (`regenerate`) |
| `projects/pdc-clicks.atomik` | Clicks through paths of different latency, used to check delay compensation by ear and in tests. | none | `crates/render/tests/console.rs` (`example`, with `ATOMIK_UPDATE_GOLDEN=1`) |
| `projects/plugin-demo/plugin-demo.atomik` | Plugin hosting with the in-repo CLAP test plugins. Build them first: `cargo build -p atomik-test-clap`. See its README. | none | `crates/render/tests/plugin_demo.rs` (`regenerate`) |
| `projects/plugin-demo-vst3/plugin-demo-vst3.atomik` | The same with both CLAP and VST3 test plugins. Build them first: `cargo build -p atomik-test-clap -p atomik-test-vst3`. See its README. | none | `crates/render/tests/plugin_demo_vst3.rs` (`regenerate`) |

Projects with audio are bundle folders: the `.atomik` file sits next to an `Audio/` folder, and you open the `.atomik` file. Plugin demos need plugin hosting enabled and the test plugins built; the test plugins are libraries from this repository (`crates/testplugins`), not third-party software.

## Patches

`patches/` holds JSON patches for the offline renderer. See [patches/README.md](patches/README.md) for the format and the three patches. Example:

```sh
cargo run --release -p atomik-render -- examples/patches/slice-demo.json -o demo.wav --stats
```
