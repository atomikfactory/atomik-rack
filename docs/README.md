## The main window

The main window has the transport bar, the arrangement, the rack, the mixer and the file browser. Each part explains its
controls in Help Mode, which links here.

- **The transport bar.** Play, Stop, Record, Loop and the metronome, the tempo and the time signature, the locators of
  the loop range, tap tempo and Q Rec (it snaps the notes you record to a grid). The bar holds what it has room for and
  the rest sits in the menu at its right end.
- **The arrangement.** One row per track, with Mute, Solo and Arm buttons, the automation lanes under it and the clips
  in time. The tools in the corner (Select, Pencil, Eraser, Razor, Speaker, Mute, Magnifier and Hand) change what a
  click and a drag do, and the snap grid next to them sets where clips and points land.
- **The piano roll.** Opens on a note clip. It has the select, pencil, eraser and razor tools, a snap grid, quantize,
  a scale with a root and a kind that notes can snap to, chord stamps, and the controller lanes under the velocity lane.
- **The expression strip.** A note can carry its own pitch, pressure and timbre curves (the three MPE dimensions,
  recorded from an MPE keyboard or drawn here). Select a note that has curves, or run Edit Note Expression from the
  command palette for any note (it also works with several notes selected), and a strip opens beside it with a tab for
  each curve. Click empty
  space to add a point and drag a point to move it (Shift moves it finely, Ctrl snaps a pitch to a semitone); Alt-click
  or double-click a point to delete it; drag from empty space to select several points and move or delete them
  together; with the Pencil tool a drag draws the curve freehand. The pitch scale button steps through 48, 24, 12 and 2
  semitones either way. Apply copies the curve of the first selected note to the other selected notes, stretched to
  each one's length. Every gesture is one undo step. The curves go out as MPE: set the MIDI Out device to a lower or
  upper zone, or press MPE on the panel of a plugin that takes plain MIDI; plugins that take note expressions get the
  curves without it.
- **The mixer.** One strip per channel, with its sections (input, EQ, compressor, sends, pan and fader), the insert
  slots, the output choice, snapshots of the whole mix and groups that move several faders together.
- **The file browser.** The places on the left, the files on the right. It sorts by name, length or size, previews
  audio when you select a file, and goes back and forward like a web browser.
- **The rack.** Each device has a name, a fold button and its own controls. Hover a knob in Help Mode to read its
  range and what its device does.

## Help Mode

Help > Help Mode, or Shift+F1, switches it on and off (F1 alone opens the list of keyboard shortcuts). While it is on, a
Help panel sits above the status line and the song gives way to it. Point at a control and the panel shows:

- **The title and the text.** The name of the control and one to four sentences about it. A knob, a switch or a choice
  of a device shows its name, its range and unit, and a line about the device it belongs to.
- **The shortcut.** The key of the command the control runs, read from your keymap, so a rebound key shows.
- **More.** A link to the section of this documentation about it; click it to open the section in the built-in manual
  (see [Manual](#manual)). Nothing is sent anywhere.

Nothing is blocked: clicks, drags and keys work as usual, and the ordinary tooltips stay off while the mode is on. The
panel keeps the last control it explained while the pointer is over empty space or over the panel itself, so the link
can be reached. A control with no help text yet shows its tooltip text instead. The mode is not saved; each session
starts with it off.

## Manual

Help > Manual (Ctrl+F1, or Cmd+Alt+F1 on macOS) opens this documentation inside the app. It works offline: the text is
the same file the documentation on the project page shows, compiled into the program, so the two never differ. The
command palette lists every section as "Manual: <heading>", and the More link of Help Mode opens the manual at its
section.

- **The table of contents.** On the left, built from the headings of the documents: this one, and the keyboard
  reference after it. Click a row to go there; the wheel scrolls the list.
- **The page.** On the right: headings, paragraphs, bold and italic text, code, lists, tables and links between
  sections, drawn in the colours of the theme. A picture is shown as its description. Up and Down, Page Up and Page
  Down, Home and End, the wheel and the scroll bar move through the page.
- **Search.** Type in the field at the top: every word must occur in a heading, or in one paragraph, list item, table
  or code block of a section. The results are ranked: a heading that equals what you typed comes first, then headings
  that start with it, then other headings, then the sections where the words occur most. Each result shows a line
  around the match with the matched words in bold. Up and Down choose a result, Enter or a click opens it, and Esc
  clears the search (a second Esc closes the manual).
- **Back and Forward.** The two buttons left of the search field, or Alt+Left and Alt+Right, step through the places
  you have been, as in a web browser. A link, a row of the table of contents and a result each add a place.
- **Links.** A link to a section of the manual moves there. A link to a page the manual does not hold (the device
  reference, the other documents of the project) opens that page in the browser, the same single request to a fixed
  address that Help > Documentation makes. Help > Documentation still opens the project page.

Esc, a click outside the panel, or Ctrl+F1 again closes the manual.

## Devices

Every built-in device has a front panel in the rack, and the device browser lists them by kind: instruments, effects,
players and mixers. Help Mode explains a device's knobs, switches and choices: point at one to read its range, its unit
and a line about the device it belongs to. Plugins in the VST3 and CLAP formats sit in the rack the same way (see
[Plugins](#plugins)).

The reference of every built-in device is [DEVICES.md](DEVICES.md): its sockets, parameters, ranges, behaviour and
limits. It is long, so the manual links to it on the project page instead of holding a copy.

## Launcher

The Launcher is a second way to make music next to the arrangement: a grid of looping clips that you start and stop
live, and that can be written into the arrangement. View > Launcher (F10) shows it where the rack is, with the
arrangement still below it; the same command hides it again. While the rack is not in the main window the launcher
takes the lower pane instead.

- **The grid.** Each note or audio track is a column, in the order and the colours of the arrangement's track list; each row is
  a scene. A slot holds one clip: its name, a small picture of its notes or waveform and a play triangle. The scene column on
  the right has a launch button and the scene's name (double click to rename it); the row under the grid has a stop
  square for each track and STOP ALL. A slot that plays has a bar along its bottom edge that follows the loop, and a
  slot that waits for its moment is outlined and blinks. Slots belong to note tracks and audio tracks.
- **Making clips.** Double click an empty slot to make a one-bar note clip and open it in the piano roll; double click
  a clip to open it. Drag a slot to another to move it, with Ctrl (Cmd on macOS) held to copy it. The right-click list
  of a slot renames it, colours it, sets its loop length (1 to 32 bars), sets its launch quantize and duplicates or
  deletes it; the list of a scene inserts, duplicates and deletes scenes. Edit > Copy, Cut, Paste, Duplicate and Delete
  work on the slot under the cursor. View > Launcher > Clip to Launcher puts the selected arrangement clip into the
  slot of its track at the cursor row, and Launcher Clip to Arrangement puts the clip under the cursor at the
  playhead.
- **Launching.** Click a slot's triangle, or move the cursor with the arrows and press Enter; Shift+Enter, or the
  triangle in the scene column, launches the whole scene. A launch waits for the next boundary of the launch quantize
  (the button on the right of the top bar cycles it; View > Launcher > Launch Quantize lists it; None, 1/16, 1/8, 1/4,
  1/2, 1 bar, 2 bars or 4 bars, 1 bar by default; a slot can have its own) and the boundaries are exact through tempo
  changes and meter changes. The clip then plays from its own start and loops. If the transport is stopped, launching
  starts it from where it stands; a position on a bar line launches at once.
- **Launching over the arrangement.** While a track plays a slot, its arrangement clips are silent. The track plays its
  arrangement again when its slot stops (the stop square under the track, or Stop All Clips: both wait for the launch
  quantize) or at once with BACK TO ARRANGEMENT, which is lit while any track plays a slot. With Scene Stops Empty
  Tracks on (the default) a scene launch also stops the tracks that play a slot and have none in that row. Notes that
  are on when a slot stops or another starts are released.
- **Record Launches.** Switch RECORD LAUNCHES on (or View > Launcher > Record Launches), then press Record. Everything
  you launch from then on is written into the arrangement when you stop: each launch becomes a clip of the slot's notes
  at the song position where it really started, as long as it played, looped when it ran longer than the slot. The
  whole pass is one undo step. No track needs to be armed; with armed tracks the notes you play are recorded as usual
  next to it. Press BACK TO ARRANGEMENT afterwards to hear the recording.
- **Audio and drags.** An audio slot holds an audio clip (its file, gain and fades) and plays it unwarped, looped over
  the length of the slot. Drop an audio file on an audio slot, or a MIDI file on a note slot, to make its clip; drag an
  arrangement clip onto a slot to copy it in, and a slot onto an arrangement lane to write a clip there.
- **Not done yet.** Warped audio in slots, launching from a MIDI controller, follow actions, and scene tempos that
  change the song tempo. The notes of a launched slot go to the track's instrument like any other notes, so a MIDI
  keyboard still plays it.

## Key and chords

The song can have a key and a chord lane. The rest of the app follows them: the piano roll, the browser, new chords
and a few tools. Nothing here changes how the song sounds.

- **The song key.** A root and a scale (major, minor, the modes, the pentatonic scales and the others of the piano
  roll; never chromatic). Click the Key field in the transport bar, or choose Transport > Song Key..., to open the
  picker and set it. The field shows the key at the playhead, so it also shows a key change once you pass one. On a
  narrow bar the field drops out and the "..." list has a Song Key... row.
- **Key changes.** The Key lane (View > Lanes and Markers > Key Lane) sits above the tracks, under the tempo and
  energy lanes. A click on the empty lane adds a key change at the snapped time, with the key already in effect
  there; a double click opens the picker on it (or a new one) so you can choose another. Drag a tag to move it. The
  tag at the start is the song key. The key at a time is the last change at or before it, else the song key.
- **The chord lane.** View > Lanes and Markers > Chord Lane. A click on the empty lane adds the tonic chord of the key
  there (minor in a minor key), one bar long or less when the next chord is near; keep the button down and drag to set
  the length. Drag a chord to move it, drag its right end to resize it, double click it to change it. Chords never
  overlap: a move or a resize that would run into the next chord stops short. Escape puts a drag back, and every
  gesture is one undo step. The right button on a chord or a tag lists Delete and Copy; on the empty lane it lists
  Add Here and, after a Copy, Paste.
- **The picker.** The Root row, the Quality rows (or the Scale rows for a key) and the Bass row pick a chord with the
  mouse. The Chord field takes a symbol: a root letter (A to G, either case) with a sharp or a flat, a quality such as
  m, min, -, maj7, M7, 7, m7b5, dim, dim7, aug, sus2, sus4, 6, m6, 9, maj9, m9, add9, 11, 13 or 5, and an optional bass
  note after a slash: Am7, F#m7b5, Bbmaj7, Dsus4/A, C/G. The buttons and the field follow each other, and a symbol it
  cannot read is explained under the field while Apply waits. Remove deletes the chord, the key change or the song key.
- **The piano roll follows the key.** A clip that has no scale of its own shows the scale of the song key at the clip's
  start: the scale highlighting, snap to scale and the fold work with it, and the scale bar shows it. A scale you set
  on the clip still wins. A new note clip has no scale, so it follows the song until you give it one.
- **Chords in the piano roll.** The Chord Stamp menu has Song Chord: the pencil drops the chord of the chord lane at the
  place you draw (a single note where the lane has no chord), with its bass note below the chord. Fit Notes to Chords
  (in the Chords menu) moves each selected note that falls outside the chord at its position to the nearest chord
  tone, a tie going down, and never onto a note that is already there; it is one undo step.
- **Detect Song Key.** Transport > Detect Song Key reads every note clip and sets the key it finds, as one undo
  step: the longer a note, the more it counts. The status line says how clear the answer was; Undo puts the old key
  back. It is a guess, and it only finds major and natural minor.
- **The browser.** Type key:song in the file browser's search to see the loops tagged with the song key (the factory
  loops carry a tag such as A minor). A song without a key filters nothing. key:minor finds the tags with that word.
- **Saving.** The key, the key changes and the chords are saved only when set, as optional fields that an older
  version of the program drops with a warning (project format 45).

## Vocal mode

The audio clip editor (double click an audio clip, or F8) has a Vocal mode for a clip of one voice at a time: a
singer, a bass, a lead. Press VOCAL in its toolbar, or 3.

- **The notes.** The editor listens to the clip and finds its notes; the footer shows how far it is and CANCEL (or
  Escape) stops it. This is not saved: it is done again when the clip opens, and quickly for a clip it has just seen.
  SENS - and + find fewer or more notes. A clip with no clear pitch (drums, noise, a chord) says "No pitched notes
  found in this clip".
- **The grid.** The waveform becomes a grid of semitones with piano keys on the left, dimmed behind the notes. When
  the song has a key, its scale is lit. Each note is a bar from its start to its end at its pitch, with the pitch
  curve through it: the original faint, the result bright.
- **Select.** Click a note; Shift+click adds or removes one; drag on the empty grid to draw a box. Ctrl+A selects all.
- **Move the pitch.** Drag a note up or down: the selected notes move by whole semitones. Hold the alternate-tool
  key (Alt, Ctrl on macOS) to move them freely, in cents. Escape during the drag puts them back.
- **Move in time.** Drag a note sideways: two warp markers are pinned at its start and end and moved together, so
  the note moves and the audio on both sides stretches. A clip without warp has it switched on at the song tempo.
- **CORRECT** brings the centre of each selected note to the nearest semitone; with **SCALE** on and a song key, to
  the nearest note of the scale. **FLATTEN** straightens the pitch drift of the selected notes by the amount beside
  it (drag the number up or down, 100% makes a straight line); a vibrato is kept. **RESET** removes the edits of the
  selected notes, or of every note when none is selected. Each is one undo step, and so is each drag.
- **The footer** names the first selected note (E3, say) with its distance from the nearest semitone in cents, before
  and after the edit, and its drift.
- **The sound.** The edits are pinned to the audio, so they stay with their notes when the tempo or the warp markers
  change, a split keeps each in the piece that holds the note's start, and a join keeps both. The clip is rendered
  with them in the background (the clip shows CALC meanwhile and plays without the edits until it is done); the
  bounce, Bounce in Place, Freeze and Export always hear them. The shift keeps the voice's character (its formants):
  it works on one note at a time, so it suits one voice and not chords.
- **Saving.** The edits are saved with the clip, as an optional field that an older version drops with a warning
  (project format 45).

## Controllers

Settings > Controllers > Set Up Controller... learns a hardware controller from the messages it sends: move each knob
and fader, press each key, and skip what the controller lacks. The wizard asks for eight knobs, eight faders, the
master fader, Play, Stop, Record, Loop, Bank Left, Bank Right and, last, Page Down and Page Up. If the controller has a
MIDI output the wizard also asks whether its knobs, faders and keys show values back (LED rings, motors, lit keys).
The result is a profile, remembered by the controller's port name, and the controller works the next time it is
plugged in.

- **Knobs and pages.** The eight knobs drive eight parameters of the selected device (or of the device the surface is
  locked to), in the order of the device's panel, leaving out the bypass switch. Page 1 is parameters 1 to 8, page 2 is
  9 to 16, and so on as far as the device goes; after the last page it wraps to the first. Page Up shows the next page
  and Page Down the previous one. Both are optional in the wizard. The commands `controller.knob_page_next` and
  `controller.knob_page_prev` do the same and have no default key (give them one in Settings > Keyboard). The status
  line names the page when it changes ("Knobs: Filter 9-16"). The page goes back to 1 when another device is
  selected, unless the profile keeps a page for each device (see below). A controller with a motor or LED ring
  receives the values of the new page at once.
- **Pick up values.** When a knob or fader is not where its parameter is (you selected another device, changed the
  page or the bank, or moved the parameter with the mouse), moving it does nothing until it comes within 2 percent of
  the value or sweeps through it, and then it takes over, so the sound never jumps. While a control waits, the status
  line says which way to turn it ("Turn knob 3 up to pick up Cutoff"). It is the same rule as MIDI learn. A relative
  encoder has nothing to catch, a parameter that steps through choices is set at once, and a fader that receives its
  value as feedback (a motorised fader) is already in place, so none of them wait.
- **The two options.** Pick up values (on for a new profile) and Keep the knob page for each device (off for a new
  profile, on remembers the page of every device for the session) are check boxes on the last page of the wizard and
  chips in Settings > Controllers while the surface runs a profile. They are saved in the profile file; a profile from
  an earlier version reads as the defaults.

## Ducking

To make one track duck under another (a bass under a kick, a pad under a vocal), right-click the track's header and
choose **Duck from**, then the track to listen to. The same submenu is in the right-click menu of the track's device
in the rack and in the strip menu of the mixer (Duck from...), and in Track > Quick Sidechain.

- **What it does.** A Compressor named "Duck from Kick" is added at the end of the ducked track's insert effects.
  Its key (the sidechain input) is the Kick's output after its fader, so the bass dips as the kick is mixed. It is set
  to a 4:1 ratio, 5 ms attack, 120 ms release and a -24 dB threshold. The toast says which knob to turn: Threshold on
  the Compressor. A lower threshold ducks deeper, and a longer release lets the bass come back later. One undo takes
  the compressor and the key cable away.
- **Pre-fader.** Duck from (pre-fader) takes the key before the source's fader and pan (its parallel output), so the
  ducking does not change when you turn the source down. A muted source gives no key either way.
- **The list.** The other tracks are listed by name, each with its colour; folders are flattened. A track that is
  already a source is marked "(ducking)". With more than thirty tracks the list stops there and More... opens a
  pop-up with all of them.
- **Again.** Ducking from a track the track already ducks from adds nothing: the compressor is selected in the rack and
  the toast says "Already ducking from Kick". Ducking from several tracks adds one compressor for each.
- **Loops.** A track cannot duck from one it feeds, such as a bus it plays into: the key would loop back. The status
  line says so and nothing changes.
- **Remove Ducking.** Takes off every compressor made this way (they are found by their name and their key cable, so
  renaming a track does not break it) and the key cables, in one step. Renaming the compressor so it no longer starts
  with "Duck from" makes it an ordinary insert that Remove Ducking leaves alone.
- **Gentle Pump.** A different, shallower way to make a track breathe: a Sidechain Tool in pump mode on quarter notes,
  with no key and no other track. It follows the song position and tempo.

## Start screen and genre templates

The start screen (File > Start Screen, and at start-up) lists New, Open, the templates and the recent songs. The first
six templates ship with the program: **Ambient**, **Hip-Hop Boom Bap**, **House**, **Lo-fi**, **Synthwave** and
**Techno**. Point at one to see its card (tempo, meter and tracks), click it to start a new song from it. File > New
from Template lists the same templates, with your own after them (at most sixteen in all). A template opens as an
untitled song, so Save asks for a place and the template itself is never changed.

- **What is in one.** A tempo and a song key, eight sections on an 8-bar grid over 64 bars (Intro, Verse or Build,
  Chorus or Drop, Break, Outro), shown as ranges in the arrangement. Six named, coloured tracks: a kick and the rest of
  the drums (the drum machine with the pads of a factory kit), a bass, chords or a pad, a lead or arpeggio and a
  texture. Their clips are the factory clips, or short patterns derived from them, laid out so the song plays from the
  first bar to the last, with some sections left bare for your own parts.
- **The launcher.** Four or five scenes hold the main loops (intro, groove, hook, break), so the launcher is full
  the first time you open it with F10.
- **The mix.** Each track sits near -18 dBFS RMS (the channel's input gain sets the level, the faders stay near
  unity). The bass has the strip EQ on and ducks from the kick (Duck from, see Ducking). Two sends feed a space reverb
  and an echo. The master has a glue compressor and a limiter with a -1 dBTP ceiling, set so the song lands near
  -14 LUFS.
- **The song information.** File > Song Information holds the title, the author (Atomik Rack factory) and a note on
  how the template is built and what to try.
- **No audio.** A template uses only the program's own devices, so it is small and plays on any machine.

## Share a project

File > Share Project (in the Project Files submenu, next to Export Project Archive) sends a song to a friend or a
collaborator as one file that opens anywhere. The panel has the **Title**, the **Author** and a **Note** (they are the
song information: SHARE writes them into it, as one undo step, when you changed them) and three check boxes:

- **Include a preview.** A listening copy of the whole song at -14 LUFS, made through the same path as Export Song as
  Audio File: an MP3 when FFmpeg is set up (Settings > Video), a 16-bit WAV file when it is not. The line after the box
  says which.
- **Include stems.** One 24-bit WAV file per mixer strip, from the stems export. It makes the share a good deal bigger.
- **Include plugin list.** The plugins the song uses, with their vendor and format, in the credits.

The line under the boxes says what the share will weigh ("This share will be about 12.3 MB"); it turns to the warning
colour above 500 MB, and the message when the share starts says the size first. SHARE asks for a file name
(`<title>.atomikz`) and writes the file on a worker, with progress in the status line and **File > Project Files >
Cancel Project Archive** to stop it; a cancel or a failure leaves no file behind.

The file is a project archive (the same stored ZIP as Export Project Archive, so any ZIP tool opens it) with more in
it: the project and every audio file it uses (taken from the project's folder, so the receiver needs neither your audio
folder nor your version of the factory library), `credits.txt` (title, author, note, the date, the version of the
program and the plugins with vendor and format, so the receiver knows what is missing), `preview.mp3` or
`preview.wav`, and the `stems` folder when asked for.

**Opening a share.** File > Open (or a drop on the window) takes an `.atomikz` file: a folder dialog asks where to
unpack it, starting in `Shared` beside the library folder (by default `Documents/Atomik Rack/Shared`), the project goes
into a folder of its own name there (`Name 2` when that exists; nothing that exists is touched), opens after the
question about unsaved changes, and the Song Information panel shows the title, author and note the sender wrote.
`credits.txt` is in the folder. A plugin the song needs that you do not have is listed the way a missing plugin
always is, and the song plays with a stand-in for it. A damaged archive, one with entries that leave its folder or
that no share holds, or one over the size limits, is refused before anything is written.

## Backup copies

Besides the project file, its versions and the autosave snapshots, Atomik Rack can keep a backup copy of every saved
project in a second folder, for example on another drive or in a folder you sync somewhere else. It is for the day a
disk fails. Settings > Backup has three controls: the **Backup folder** (None until you choose one, with **Choose...**
and **None**), **Keep** (how many copies of each project stay, 1 to 50, 10 by default; Shift moves it by ten) and
**Include audio** (on by default).

Every successful save, File > Save, Save As, Collect Files and Move Project alike, then copies the project into
`<backup folder>/<project name>/<project name> <date and time>.atomik` (the time is UTC, to the second, like
`Song 2026-11-10 093112.atomik`). With Include audio the audio files the project uses go into
`<backup folder>/<project name>/Audio/`. Audio is named by its content, so a file is copied once and later saves find it
there. The copy runs on its own worker after the save is done: it never delays a save and never fails one. Autosave
snapshots are for crash recovery and make no backup.

When there are more than **Keep** copies the oldest are removed. An audio file goes only when no copy that stays names
it: every project file in the project's backup folder is read first, and if one cannot be read no audio is removed at
all. Files you put there yourself that are not copies of this project are never touched. Two projects with the same
name share one folder in the backup folder, so give them different names.

If a copy fails (the folder is gone, the disk is full) the status line says `Backup failed: <the reason>` once per
session and every later failure goes to the log only; the save itself is fine and the next save tries again.

**File > Restore from Backup...** lists the copies of the open project, newest first, with the date and the size of
each. Choose one (Up and Down, a click, then RESTORE or Enter; a double click restores at once) and it opens as a new
unsaved song, like a template: it is never the song's file, so neither the copy nor the project is overwritten, and
Save asks where to keep it. The question about unsaved changes comes first. Its audio comes from the copy's own
`Audio` folder (a copy made without Include audio opens with its audio listed as missing, to be relinked).

## Themes

Atomik Rack has three themes: **Dark** (the one it always had), **Light**, and **Synthwave**, a neon night with a deep
indigo background, hot magenta and electric cyan accents, a magenta grid in the arrangement and meters that run cyan,
magenta and orange. **Settings > Themes** lists them with a row of sample colours each; a click on one uses it at once,
in every window and panel, and it is kept for the next start. View > Theme has the same choices (Dark, Light, Same as
System) and **Next Theme**, which steps through the whole list, and **Theme Manager...** opens the tab. The Theme row of
Settings > Interface shows the theme in use; stepping it goes back to Dark, Light and Same as System.

Your own themes are files. Below the list:

- **Duplicate** makes your own copy of any theme, named "<name> copy". Dark, Light and Synthwave cannot be changed or
  deleted, so a copy is how you start.
- **Rename** types a new name in the row (Enter keeps it, Esc leaves the old one). Two themes cannot share a name.
- **Delete** asks first. If the theme was in use, the choice goes back to Dark, Light or Same as System.
- **Edit...** opens the theme editor on one of your themes.
- **Import...** takes a theme file (`.json`), checks it, and copies it into the themes folder (with a number after the
  name if the name is taken). **Export...** saves the selected theme as a `.json` file you can share.
- **Open Themes Folder** shows the folder in the file manager: the `themes` folder next to `settings.json`. A theme
  is one `.json` file there, and you can edit it with any text editor (docs/EXTENDING.md, "Making a theme", has the format).

A file that is not a theme (it is not JSON, it has a colour that is not `#rrggbb`, or it is a newer version of the
format) is skipped when the program starts, with one message that lists the files and one line in the log; the file is
never touched. A theme that leaves a colour out takes it from the built-in theme it is based on, Light or Dark.

### The theme editor

The editor lists every colour of the theme in groups (Backgrounds, Text, Accents, Meters, Arrangement, Rack and
Console). Each row has a swatch and the colour as text:

- Click the **swatch** to open the colour picker; **Apply** gives the colour to that row.
- Click the **hex text** and type a colour, `#rrggbb` or `#rrggbbaa` when the colour is see-through. The row changes as
  soon as the text is a colour.
- **RESET** (shown on a row that differs from the theme it is based on) sets the colour back to the base theme's.
- **UNDO**, or Ctrl+Z (Cmd+Z on macOS), takes back the last change; the history lasts until the editor closes.
- Up and Down move to the next row, **SAVE** (Ctrl+S) writes the file, and **CLOSE** (Esc) writes it too when
  something changed.

Every change shows at once in the whole program behind the editor, including the part of the theme in use. When the
editor closes the program goes back to the theme in use. The colour tokens:

| Group | Tokens |
| --- | --- |
| Backgrounds | `background`, `rail`, `rail_hole`, `ear`, `panel_top`, `panel_bottom`, `back_top`, `back_bottom`, `plate`, `lcd`, `button`, `browser_bg`, `browser_row`, `tooltip_bg`, `error_bg`, `bevel_light`, `bevel_dark`, `section_line`, `ink`, `veil`, `dim` |
| Text | `text`, `text_muted`, `on_accent`, `on_dark`, `on_error` |
| Accents | `highlight`, `focus`, `selection`, `warning`, `mute` |
| Meters | `meter_low`, `meter_mid`, `meter_high` |
| Arrangement | `lane`, `lane_alt`, `lane_auto`, `grid_bar`, `grid_beat`, `grid_sub`, `row_black`, `key_white`, `key_black` |
| Rack | `screw_light`, `screw_dark`, `knob_top`, `knob_bottom`, `knob_track`, `knob_pointer`, `jack_light`, `jack_dark`, `jack_hole`, `led_off`, `cable_audio`, `cable_cv`, `cable_notes`, `cable_insert`, `cable_send`, `cable_sidechain`, `cable_shadow` |
| Console | `io_connected`, `io_free`, `io_unavailable`, `clip` |

Besides the colours a theme file can set `dark` (light type on dark surfaces), `accent_saturation` and
`accent_lightness` (the colours the devices and tracks get when nothing names theirs; Synthwave's are neon) and
`corner` (the panel corner radius). Keep the text readable: the built-in themes keep their body text at a contrast
of at least 4.5 to 1 against every panel, and a theme you make is not checked.

The theme in use is a preference, not part of a project: songs look the same in every theme, and nothing about the
theme is saved in them.

## CPU use

The program times every device in the rack on the audio thread all the time; the cost is small (about half a percent
of a 64-frame callback for a hundred devices) and it never changes the sound. What it shows is the share of the
audio time a device uses: 100 % means the device alone takes as long as the audio it makes.

- **On the devices.** View > Show Device CPU (off at the start, not saved) puts a small figure on the name plate of
  every device in the rack, such as `3.2%` (one decimal below 10 %, whole percent above), averaged over about a second.
  A container shows the sum of the devices inside it. A figure above 25 % turns the warning colour of the theme.
- **On the mixer.** With the same switch on, each channel strip shows the total of its track in the top right corner of
  the name plate: the instrument, the channel and its insert effects.
- **The status line.** Rest the pointer on the status line at the foot of the window: the tooltip gives the engine load
  and its peak, then the five heaviest devices with the track each one belongs to and its own peak (held for two
  seconds). A plugin in its own process counts the time the program waits for it.
- **The hint.** When the engine load stays above 70 % for five seconds while the song plays, a card above the status
  line says which track uses the most CPU, such as "Track Bass uses the most CPU (41%). Freeze it?". Freeze runs Freeze
  Track on it (Unfreeze undoes it); Not now closes the card. Each track is suggested at most once per song, and a frozen
  track or one without clips is never suggested.

## Plugins

Options > Plugin Manager is the place to find, organise and fix the third-party plugins (VST3 and CLAP). Turning
plugins on, the scan folders and the sandbox stay in Audio > Plugins.

- **The table.** One row for every plugin the scan found: name, vendor, format, category (what the plugin says it is:
  instrument, effect or note effect), status, file and the time of its last scan. A file that failed to scan is a row
  too, with its reason in the status. Click a column head to sort, again to reverse. The star column sorts the
  favourites first.
- **Search and filters.** The search field finds a word in the name, vendor, path or a tag. The four buttons beside it
  step through their choices on each click: format (all, VST3, CLAP), status (all, OK, failed, unsupported,
  quarantined, disabled), category and tag.
- **Choosing rows.** A click chooses a row, Ctrl (Cmd on macOS) toggles one, Shift chooses a range and Ctrl+A all the
  rows shown. The buttons act on the chosen rows.
- **Favourites.** Click the star of a row, or press Space on it. In the device browser the starred plugins come first,
  in a Favourites group and at the top of their kind.
- **Tags.** Type a tag in the Tag field and press Add Tag (or Enter): the chosen plugins get it. The tags of the first
  chosen plugin are listed beside the field; click one to take it off. In the device browser type `#` and the start
  of a tag in the search field to list the plugins that have it. Tags are the same words as in the file browser.
- **Disable.** Hides the chosen plugins from the browser and the menus. A project that uses a disabled plugin still
  loads it, and Enable shows the plugin again.
- **Quarantine.** A plugin whose process ends, or that cannot be loaded, three times in a row is quarantined: it is
  hidden like a disabled one and a message says so once. An instance that ends without a fault, or a load that works,
  starts the count again. Try Again takes the chosen plugins out of quarantine (and scans failed files again).
- **Rescan.** Rescan All scans every plugin folder again, Rescan Selected only the files of the chosen rows. The scan
  runs in the background: the panel shows how far it is and the same button becomes Cancel.
- **Show in Folder.** Opens the file manager at the file of the first chosen row.
- **Where it is kept.** Favourites, tags, disabled plugins and the quarantine are saved by the plugin's own id in
  `plugins_user.json` beside the settings file, so they stay with a plugin that moved to another folder. A missing or
  damaged file reads as empty.

## Windows

The rack and the mixer can leave the main window (View > Panels > Detach Rack and Detach Mixer, or by closing their
window to put them back). The main menu bar is at the top of each of those windows, the same bar as in the main window:
the same menus, the same check marks and the same dimmed items, so a command is always one click away from the window
you work in.

- **Which pane a command acts on.** A command that works on "the pane with the keys" works on the pane of the window
  whose bar you used. Edit > Select All, Copy, Cut, Paste, Duplicate and Delete act on the rack devices in the rack
  window and on the mixer strips in the mixer window. Keyboard shortcuts work in every window as before.
- **One open menu.** Only one menu is open at a time. Opening a menu in one window closes the one open in another, and
  a menu closes when its window loses the focus. While a menu is open the arrow keys, Home, End, Enter and Escape work
  it, in whichever window it is; there are no Alt or letter shortcuts for the menu titles.
- **Size.** A window with the bar is never narrower than the bar. The window's size and place are saved as before.
- **No bar.** The small windows (Spectrum EQ, Piano Keys, Video) and the detached browser have no menu bar. On macOS the
  menu bar is the system's, at the top of the screen, and the windows draw none.

## Privacy

Atomik Rack sends nothing about the user or the computer. Its only network request is the optional check for a newer
version (Help > Check for Updates, and once a day when the user said Yes to the question at the first start): one
HTTPS request to the project's page for the list of releases, carrying only the program name and version as the
User-Agent. Nothing is downloaded or installed, and until the question is answered nothing is sent. How it works is in
[ARCHITECTURE.md](ARCHITECTURE.md#the-update-check); the choice is in [DECISIONS.md](DECISIONS.md#s-the-update-check).
